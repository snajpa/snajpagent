snajpagent

A terminal harness for autonomous, long-horizon work and distributed agent teams.

Model-owned notes in your repositories carry findings, decisions and unfinished work between sessions. Sessions start in your home directory and discover its AGENTS.md instructions, where you can point the model to that shared memory.

Downloads · README · Manual · Source

The guide and web manual describe current source. Each release download includes its matching manual. An updated executable takes effect on the next launch; open sessions keep their original code.

Work on a project

Give a model an objective, constraints and project context. Persistent goals carry implementation, testing and follow-through across turns; steering and saved sessions keep that work under your direction. Connect agents across machines and rooms to divide work and exchange findings while each runs tools in its own environment.

Start snajpagent and describe the task. Sessions start in your home directory; the model manages its working directory. Tools read and edit files and run commands across the filesystem with your OS permissions, without per-call approval. Tool details are hidden at the default verbosity; show them when useful. Read replies and scroll back normally.

You can type while work continues. Send a correction to change the current task, or queue a follow-up to run afterward. Commands already running stay alive; the model can let them finish or stop them. A submitted correction stays visible in rollout even when the next prompt is blocked.

With current source, a reply while commands are running waits for your input or command completion. Output keeps buffering; /yield returns control to the model.

Foreground slash commands finish before another command runs. Controls needing a safe boundary acknowledge it. The prompt shows context usage. /history N shows retained turns; /cat PATH opens a file in your pager. Current-source keyboard command reports, including /status and /history, use $PAGER, or less -FX when unset and less is available, for scrolling and search. Short reports return automatically. Work and IRC continue while the pager is open; new output appears when it closes. /ro QUERY queues read-only inspection, and /compact summarizes context while preserving the local log.

Resume continues unfinished work without a new prompt. For scripts, use snajpagent -e --resume SESSION_ID </dev/null. Calls with uncertain outcomes retain their original commands for inspection.

Current Linux source starts detachable sessions on ANSI terminals at least 20 columns wide. Use /s d to return to the shell while work continues, then snajpagent --attach SESSION_ID to reconnect with the retained draft. Without an ID, attach lists running sessions. Current source accepts -N NAME to name a new session and select it on attach or resume; /session name NAME names an existing session. --resume attaches to a running owner and restarts a stored session. Session lists show attached, detached, running (attachment status unavailable) or stored with prompts and IRC nick@endpoint (s/ server, c/ client). snajpagent -l lists all attached sessions, then all detached sessions, then those with unavailable attachment status, then the 10 most recent stored sessions, newest activity first in each group. Use -l N to change the stored count, or -l 0 for running sessions only. Resume retains saved settings unless overridden. Terminal file transfers and local audio stop on disconnect; queued downloads keep their saved state. Restart microphone capture explicitly after reconnecting.

Set a goal to continue beyond the next reply. Active goals continue on resume; pause before exiting to keep one paused. /goal resume continues work; /goal clear ends continuation and retains history. Resume preserves inputs and tool results; uncertain commands require inspection.

For longer work, have the model keep findings, decisions and corrections in project files, with pointers in AGENTS.md. Keep the notes current so later tasks can use what was learned and pick up unfinished work.

Stage images or files with /attach PATH and submit them with your prompt. Current source provides a workstation wrapper: snajpagent remote ssh -t target snajpagent. For stock Mosh use snajpagent remote mosh target snajpagent: a checked, slower screen-state mode keeps transfer frames out of scrollback. Remote tmux supports transfers with one writable client focused on the agent pane. Detach with /session detach and reconnect through snajpagent remote ssh -t target snajpagent --attach SESSION_ID. Omit the ID to choose a running session. Use /receive to select a workstation file, then review /attachments before submitting. Use /send PATH to save a remote file under ~/Downloads. Transfers preserve the conversation. Detached exports stay queued: fast-stream reattachment delivers them automatically; on Mosh use /send PATH. Receipts identify local paths. The trzsz-go wrapper remains an alternative for explicit transfers (brew install trzsz-go on macOS, then trzsz --dragfile ssh target). See the manual's Terminal file transfers section.

/dictate inserts speech into your draft. /voice on starts conversation audio, /voice mute pauses the microphone and /voice off stops it. Speech can inspect status, steer or queue coding work while preserving your typed draft. The model can reply with voice_output.

Voice uses your selected provider's credentials. A codex-lb gateway needs its /backend-api/codex base. Use HTTPS or a secure tunnel outside trusted networks. The manual covers supported providers, data destinations and capture controls.

Coordinate distributed work

People and agents connect through built-in IRC servers and clients. Each instance can connect to several endpoints and channels; /connect ENDPOINT joins that endpoint's advertised room. Empty Tab cycles through rollout, connected rooms and opened private chats. Open a private tab with /query NICK or join a channel with /join ENDPOINT/#CHANNEL. Conversations keep their own drafts, nickname completion and unread indicators. Enter sends to the selected operator conversation and directs your own agent in rollout.

Models select room messages, sleep IRC delivery and compact context; your transcript stays complete.

Start a room and connect another instance in a separate terminal:

snajpagent -s
snajpagent -c

These defaults connect on localhost. Give agents tasks in the room; they can exchange messages and report results. How you divide the work is up to you.

Agents can use project files and Git for code and handoff notes; arrange access to those files separately. IRC has no authentication or TLS. Use localhost, a trusted network, or a secure tunnel. Tools run with your local permissions, without a command-approval sandbox.

Run it where the work is

Download 0.99.8c for Linux, macOS, Windows or BSD, or build from source. The downloads page lists architectures and requirements.

A normal build needs C11/POSIX with pthreads, GNU make, libcurl and Jansson. ./configure probes the compiler and the optional modalities and reports what it enabled and disabled:

git clone https://github.com/snajpa/snajpagent.git
cd snajpagent
./configure
make
sudo make install

On a fresh launch without configuration or credentials, interactive setup helps you choose a provider and supported model. The README covers setup and platform-specific builds; the manual covers the complete controls and configuration.

Supported providers

Supported connections: OpenAI, ChatGPT/Codex subscription, OpenRouter, and custom providers with an OpenAI-compatible Responses API.

Enterprise Codex access tokens use snajpagent login codex --with-access-token, reading the token from stdin. Select the Codex provider for subsequent sessions; see the login reference.

Refresh available models with /model cache. The model's select_model tool, enabled with [agent] allow_model_change=true (default off), chooses from the current cache and can refresh it before selecting a newly listed model. Current source adds /fast to toggle priority service with ON/OFF feedback; provider support and pricing apply.

  • OpenAI GPT-5+: recommended; the only model family thoroughly tested and known to work reliably with snajpagent.
  • DeepSeek: an open-model option. V4 Pro supports direct Responses streaming with reasoning continuity across tool calls and resume in current source.
  • Anthropic: not supported. The project's assessment is that alignment problems make its models unsuitable for long-horizon autonomous work without oversight.
  • Other models: use at your own risk. GLM is discouraged, as are open models trained heavily on Anthropic rollouts.
