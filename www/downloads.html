Choose the right build

  • Linux: choose x64 for Intel/AMD 64-bit PCs or ARM64 for AArch64 machines. Both builds statically link musl and application libraries. They do not require Nix, system libcurl, or a matching glibc. Earlier builds were exercised on Alpine 3.22.5 / Linux 6.12; that is not a promise of compatibility with every older kernel.
  • macOS: universal contains both Intel and Apple Silicon slices. Application libraries are included, but Apple's system library is still required. The build deployment target is macOS 11; actual macOS runtime qualification is pending. Builds are ad-hoc signed, not Developer ID signed or notarized.
  • Windows: the x64 executable includes application libraries and uses only Windows system DLLs. Runtime checks have run in modern Windows PE; a Windows 7 compile target is not a Windows 7 compatibility claim. ARM64 and older Windows qualification remain in progress, outside the current production matrix.

The portable builds include TLS and CA roots; there is no first-run library or certificate download. Build success and runtime qualification are different. Each release must identify its actual test scope and limitations; consult the dependency and platform notes.

Using a release binary

When assets are published, download the file for your OS and architecture and verify it against that release's SHA256SUMS. On Linux or macOS, rename it to snajpagent and make it executable with chmod +x snajpagent. On Windows, keep the .exe extension. Matching debug symbols are optional, separate downloads.

Run it in your project directory and follow the provider setup prompts. Start with rollout and steering, then native networking. Tools run with your local permissions; the program is not a command-approval sandbox.
