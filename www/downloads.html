Choose the right build

  • Linux: choose x64 for Intel/AMD 64-bit PCs or ARM64 for AArch64 machines, or i686 for 32-bit x86. These builds statically link musl and application libraries. They do not require Nix, system libcurl, or a matching glibc. These release files passed local provider, resume and TLS checks on native x64/i686 and emulated AArch64. Earlier builds were exercised on Alpine 3.22.5 / Linux 6.12; neither is a promise of compatibility with every older kernel. i686 does not imply Linux 2.4 support.
  • macOS: universal contains both Intel and Apple Silicon slices. Application libraries are included, but Apple's system library is still required. The build deployment target is macOS 11; actual macOS runtime qualification is pending. ARM64 is ad-hoc signed; Intel is unsigned. Neither is Developer ID signed or notarized.
  • Windows: choose x64 or native ARM64. Both include application libraries and use only Windows system DLLs; ARM64 uses the OS UCRT. Earlier development builds were checked in Windows PE build 26100 (x64) and 28000 (ARM64); these release binaries were not executed on Windows here. Full desktop and older Windows qualification remain in progress; a Windows 7 compile target is not a Windows 7 compatibility claim.

The portable builds include TLS and CA roots; there is no first-run library or certificate download. Build success and runtime qualification are different. Each release must identify its actual test scope and limitations; consult the dependency and platform notes.

Using a release binary

Download the file for your OS and architecture and verify it against that release's SHA256SUMS. On Linux or macOS, rename it to snajpagent and make it executable with chmod +x snajpagent. On Windows, keep the .exe extension. Matching debug symbols are optional, separate downloads.

Run it in your project directory and follow the provider setup prompts. Start with rollout and steering, then native networking. Tools run with your local permissions; the program is not a command-approval sandbox.
